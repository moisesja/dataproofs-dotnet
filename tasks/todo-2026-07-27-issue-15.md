# Issue #15 — non-string unprotected `header.kid` must throw MalformedJoseException

Issue: https://github.com/moisesja/dataproofs-dotnet/issues/15

`JwsParser.ExtractSignatures` reads the JWS unprotected header's `kid` with
`JsonElement.GetString()` without a `ValueKind` guard (flattened `:303`, general `:329`).
A non-string `kid` (number/object/array/boolean) escapes as a raw
`InvalidOperationException`, violating the documented `MalformedJoseException` contract
(`JwsParser.Parse` XML doc). Reachable pre-authentication — structural enumeration runs
before any signature check.

Fix chosen: the **strict** option, per the issue author's stated preference — a present,
non-null, non-string `kid` throws `MalformedJoseException` (RFC 7515 §4.1.4: `kid` is a
string; silently ignoring it hides a broken sender). `kid: null` and absent `kid` keep
today's behavior: fall back to the protected header's `kid`.

Session note: non-interactive session; the issue itself is the user's detailed spec
(fix shape + preference + test list), so implementation proceeds without a plan-approval
round-trip. The PR remains the approval gate (nothing merges to main here).

## Review

- **Root fix** (`src/DataProofsDotnet.Jose/Signing/JwsParser.cs`): both unguarded unprotected-`kid`
  reads replaced by one `ReadUnprotectedKid` helper. A present, non-null, non-string unprotected
  `kid` now throws `MalformedJoseException("JWS unprotected header 'kid' must be a string.")` during
  structural enumeration — the same stage where the raw `InvalidOperationException` used to escape.
  Chose the strict option per the issue author's stated preference (RFC 7515 §4.1.4).
- **Follow-up fix (same file):** `ParseJsonCore` now wraps `JsonDocument.Parse` in
  `try/catch (JsonException) ⇒ MalformedJoseException`. Caught by the adversarial subagent: the
  parser's own entry point leaked a raw `System.Text.Json.JsonException` on any malformed/truncated/
  duplicate-member/over-deep input — the identical "untyped fault escapes pre-verification" class the
  issue is about, and strictly more reachable (a partial WebSocket frame is malformed JSON). Both
  sibling parsers already wrapped this call; `JwsParser` was the outlier. This is the
  `tasks/lessons.md` 2026-06-22 rule in action ("close every channel of the same class, not just the
  headline one").
- **Preserved behavior** (tests): `kid: null` and absent `kid` fall back to the protected-header
  `kid`; matching string kids in both headers verify and report the kid; non-object `header` still
  treated as absent (unchanged, out of scope).
- **Tests:** 14 new cases across 4 `[Theory]` methods — flattened non-string kid (4) + general
  non-string kid (4) + malformed JSON (4) + absent/null fallback (2). Jose suite 351/351; full
  solution **832 passed, 0 failed, 0 skipped**.
- **PR review (repo owner):** removed a redundant `matching-string-kid-in-both-headers` fixture that
  asserted an RFC 7515 §5.2-nonconformant shape (duplicate `kid` across the protected/unprotected
  headers) as valid; corrected the "14 tests" wording (it counts cases, not methods) and the "CI
  green" claim (`ac-9 samples coverage gate` is red on base `main` @ `2db3cd8`, pre-existing —
  8 uncovered ECDH/JWE members, unrelated to this PR); split the AngleSharp floor-lift into its own
  commit. **Parser follow-up (not in scope here):** the parser accepts a both-present *matching*
  `kid` (issue #10's agreement check), which RFC 7515 §5.2 step 4 forbids regardless of match —
  flagged to the owner as a separate conformance decision, since fixing it reverses the issue #10
  rule and changes that issue's regression-test message.
- **Adversarial review:** subagent swept every typed `JsonElement` accessor reachable
  pre-verification across `DataProofsDotnet.Jose`; the only residual was the `JsonDocument.Parse`
  leak (now fixed). Confirmed no other unguarded `GetString`/`GetInt`/`EnumerateArray`, throw
  propagation is clean (thrown in `ParseJsonCore` before `VerifySignatures`, not swallowed by its
  per-signature catch), duplicate members are rejected deterministically by
  `JoseJson.StrictDocument`, and the AngleSharp lift is inert (Rdfc not in Jose's dependency chain).
- **API surface:** unchanged (`ReadUnprotectedKid` is private); `ApiSurface.Tests` green.
