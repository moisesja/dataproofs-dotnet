## Facts established by scratch spikes (outside the repo), which shape the design

1. **A `JsonSerializerContext` constructor locks the options it binds to.** `TypeInfoResolverChain`
   cannot be modified afterwards (`InvalidOperationException`). So the reflection fallback must be
   chained *before* freezing, and typed infos are obtained with `options.GetTypeInfo(typeof(T))`
   (AOT-safe, not annotated) rather than from a context instance bound to the shared options.
2. **The `IsReflectionEnabledByDefault` guard does not silence the Roslyn analyzer.** The ASP.NET
   Core pattern is needed: a tiny method with `[UnconditionalSuppressMessage("Trimming","IL2026")]`
   / `("AOT","IL3050")` whose body is `if (JsonSerializer.IsReflectionEnabledByDefault) chain.Add(new
   DefaultJsonTypeInfoResolver())`. ILC substitutes the switch to `false` in trimmed/AOT hosts and
   removes the branch, so the reflection resolver is never rooted.
3. **The .NET 10 generator models `init` properties as pseudo-constructor parameters.** Two
   consequences on `DataIntegrityProof` (a `sealed record` with `init` members):
   - an `init`-only `[JsonExtensionData]` bag throws at first use: *"The extension data property
     'AdditionalProperties' … cannot bind with a parameter in the deserialization constructor"*;
   - an `init` member **with an initializer** (`Type = "DataIntegrityProof"`) comes back `null` when
     absent from the payload, whereas reflection keeps the default.
   Verified fix: make exactly those two properties `{ get; set; }`; all other `init` members behave
   identically (serialization bytes identical, `with` expressions still work, duplicate-member
   rejection still works).
4. **A downstream source-gen context cannot include `DataIntegrityProof` today** (SYSLIB1220/1030):
   `PreviousProofReferenceJsonConverter` is internal, so a consumer's generator cannot instantiate it.
   zcap-dotnet (#154) will need exactly this.
5. Reflection vs source-gen bytes are identical for the model shape (member order, `WhenWritingNull`,
   extension data last, `UnsafeRelaxedJsonEscaping` honored through `GetTypeInfo`-derived infos).
6. The local toolchain can native-AOT publish (SDK 10.0.100, Apple clang), so every step below is
   verified locally before CI.

## Decisions (owner may amend at approval)

1. **Version stays 1.4.0 (owner's decision at plan review: prepared, not deployed).** No
   `Directory.Build.props` change. The AOT work joins the existing `## [1.4.0]` CHANGELOG entry as new
   `### Added` and `### Changed` sections ahead of its `### Fixed`; the "why minor" paragraph gains one
   sentence covering the two source-compatible API loosenings and the resolver-semantics change, which
   fit a minor on their own. The entry's date is re-checked at tag time (RELEASING.md step 2).
2. **Public API changes (source-compatible, recorded in `PublicAPI.Unshipped.txt`):**
   - `DataIntegrityProof.AdditionalProperties` and `DataIntegrityProof.Type`: `init` → `set` (fact 3).
     Object initializers and `with` keep compiling; already-compiled dependents rebuild (binary
     compatibility is out of scope per RELEASING.md; recorded as a migration note).
   - `PreviousProofReferenceJsonConverter` becomes `public sealed` (fact 4) so consumers can put
     `[JsonSerializable(typeof(DataIntegrityProof))]` in their own contexts. Its members are
     invoked by System.Text.Json, never by user code → `tasks/samples-coverage/allowlist.txt` entries
     with that justification (AC-9), unless a sample naturally names it.
   - Nothing else: no new public resolver/context surface.
3. **`DataProofsJsonOptions.Default` keeps JIT behavior.** Resolver chain = [Core source-gen
   context, then `DefaultJsonTypeInfoResolver` only when `JsonSerializer.IsReflectionEnabledByDefault`].
   The library's own types therefore never resolve through reflection in any host, and consumer types
   keep working in JIT hosts exactly as today. In trimmed/AOT hosts (and `PublishAot` projects, where
   the SDK turns the switch off even under `dotnet run`), a consumer type without metadata fails with
   System.Text.Json's own `NotSupportedException` naming the type — documented in the XML doc, README
   and CHANGELOG.
4. **One internal context per package, bound to a copy of the shared options** (not
   `InternalsVisibleTo` across packages, not a public context): Core `DataProofsJsonContext`
   (`DataIntegrityProof`, `JsonObject`, `JsonNode`, `JsonElement`); Jose `JoseJsonContext`
   (`JwsProtectedHeader`, `JweProtectedHeader`, `Jwk`, `string`) bound to `JoseJson.Default`; Rdfc and
   Legacy each a 3-type context bound to `new JsonSerializerOptions(DataProofsJsonOptions.Default)`
   with their own resolver (same encoder/ignore settings → same bytes). A missing type then fails fast
   in the ordinary JIT test run (no silent reflection fallback inside the packages).
5. **Escaping and member order are preserved everywhere**, including the one inconsistency found:
   `JweBuilder.RenderJwe` serializes with *default* options (HTML-safe escaping) while
   `JwsBuilder` renders with the relaxed encoder. Preserved deliberately (issue: "escaping must not
   change"); pinned by a test; noted in the CHANGELOG as pre-existing.
6. **Enforcement:** `<IsAotCompatible>true</IsAotCompatible>` in each of the six `src` csproj files
   (explicit per project; `Directory.Build.props` would also hit tests/samples/tools). With the
   repo's `TreatWarningsAsErrors` every new IL2xxx/IL3xxx fails the build. No `BannedSymbols.txt`
   change: redundant with the analyzers and it would have to exempt the guarded fallback.
7. **Gate = new tool `tasks/aot-smoke` + CI job `ac-12`**, mirroring `tasks/smoke` conventions, in
   the .sln (so `/warnaserror` builds it) with `PublishAot` passed on the publish command line so
   solution restores do not pull ILCompiler. PRD gains **NFR-7** (AOT/trimming) and **AC-12**.
8. **Adversarial review** (CLAUDE.md §2) runs before "done", twice: once on the change, once on the
   fixes to its findings. Findings and dispositions go in the task record.
9. Push the branch and open a PR (`Closes #27`) as with #29. **No tag, no publish.**

## Design

### Core (`src/DataProofsDotnet.Core`)
- `DataProofsJsonOptions.cs`: build options → `TypeInfoResolver = DataProofsJsonContext.Default` →
  `AddReflectionFallbackForJitHosts(options)` (suppressed, guarded) → `MakeReadOnly()`. Internal
  typed accessors: `internal static JsonTypeInfo<DataIntegrityProof> Proof`, `JsonObject`,
  `JsonNode`, `JsonElement` via `(JsonTypeInfo<T>)Default.GetTypeInfo(typeof(T))`. XML doc rewritten to
  state the resolver semantics (decision 3).
- New `DataProofsJsonContext.cs` (internal partial `JsonSerializerContext`, `[JsonSourceGenerationOptions]`
  mirroring the options: no naming policy, `WhenWritingNull`, `WriteIndented=false`).
- `DataIntegrityProof.cs`: `Type` and `AdditionalProperties` → `set`, with a remarks paragraph saying
  why (fact 3). `PreviousProofReferenceJsonConverter` → `public sealed`, documented.
- Call sites (`DataIntegrityProofPipeline.cs`, `JcsCryptosuite.cs`): `SerializeToElement(x,
  DataProofsJsonOptions.Default)` → `SerializeToElement(x, DataProofsJsonOptions.Proof /
  .JsonObject)`, `SerializeToNode(proof, …Proof)`, `proofElement.Deserialize(…Proof)`.
- `PublicAPI.Unshipped.txt`: two `.init` → `.set` lines; converter type + ctor + `Read`/`Write`.

### Jose (`src/DataProofsDotnet.Jose`)
- `Json/JoseJson.cs`: same pattern (no reflection fallback — internal options). New
  `Json/JoseJsonContext.cs`. `[JsonSourceGenerationOptions(AllowDuplicateProperties = false, …)]`
  matches `Default`. Typed accessors `JoseJson.JwsHeader`, `JweHeader`, `Jwk`, `String`.
- Remove the `HeaderContext` alias class (two call sites) in favor of the typed accessors.
- `JwsProtectedHeader.cs`, `JweProtectedHeader.cs`, `SdJwtClaims.cs`: typed overloads.
- `JweBuilder.RenderJwe`: anonymous type → `JsonObject` with the same member order, rendered with
  `ToJsonString()` (default options, as before). `VcJose.cs:60`: `SerializeToElement(…, JoseJson.String)`.
- `SdJwtIssuer.cs:138,162`, `JwsBuilder.cs:213`: `JsonArray.Add((JsonNode)…)` / `JsonValue.Create(string)`.

### Rdfc and Legacy
- `Rdfc/DataIntegrity/RdfcJson.cs` and `Legacy/DataIntegrity/LegacyJson.cs`: internal context
  (`DataIntegrityProof`, `JsonObject`, `JsonNode`) + options copy + typed accessors (decision 4).
- `RdfcCryptosuite.cs`, `Bbs2023Cryptosuite.cs`, `LegacyCryptosuiteBase.cs`: typed overloads.
  `StripNullMembers` returns `JsonNode?` → `JsonNode` typed info (null serializes as `null`, as before).

### Declaration and hygiene
- `<IsAotCompatible>true</IsAotCompatible>` in all six src csproj files (Cose and DI included: they
  must stay clean and carry the trimmable metadata too).
- `tests/DataProofsDotnet.ApiSurface.Tests/PublicApiHygieneTests.cs`: new fact asserting every

## Decisions made during implementation

- **Typed-info accessors, not context instances.** Because a bound context locks the options, each
  package exposes `JsonTypeInfo<T>` accessors obtained with `options.GetTypeInfo(typeof(T))`
  (`DataProofsJsonOptions.ProofTypeInfo` …, `JoseJson.*TypeInfo`, `RdfcJson`, `LegacyJson`); every
  context is `GenerationMode = Metadata` because the bound options, not the attribute, carry the wire
  settings. `HeaderContext` (the `JoseJson.Default` alias) was removed.
- **Legacy joins the ApiSurface hygiene sweep.** It had never been scanned; the new
  `EveryPackage_DeclaresTrimAndAotCompatibility` fact needs all six, so the sweep's assembly list gained
  the Legacy assembly (anchored on `LegacyCanonicalization`) — the existing sweeps pass on it.
- **AC-9 allowlist, two entries** for the public converter (type and ctor): applied through the
  `[JsonConverter]` attribute and instantiated by System.Text.Json or by consumer source generators,
  so no sample can name it. AC-7 BCL allowlist gains `System.Type` for its `Read` signature.
- **`JweBuilder.RenderJwe` keeps the default encoder** (decision 5), pinned by `JweRenderingTests`
  against the former anonymous-type rendering produced by the former code.
- **`tasks/aot-smoke` was delegated to a subagent**, which stopped on a usage limit after writing the
  project file, the consumer context and the fixture/report helpers. The paths and the three modes were
  finished in the main session on that foundation. The tool declares its own consumer
  `JsonSerializerContext` listing `DataIntegrityProof`, the downstream (zcap-dotnet) scenario that fact
  4 unblocked.
- **Finding from the tool's first reflection-disabled run: hidden reflection in NetCid.**
  `JcsCanonicalizer.Canonicalize(JsonNode)` serializes the node with reflection-based System.Text.Json.
  NetCid has no AOT annotations, so the analyzers were silent. The JCS verify path called it whenever
  the proof carries `@context`, so every JCS verification failed closed in trimmed/AOT hosts
  (`PROOF_VERIFICATION_ERROR … (InvalidOperationException)`). Fixed by canonicalizing a `JsonElement`
  (`91ebbfb`); the four `JsonNode` overloads are banned in `BannedSymbols.txt`, with a positive control
  that RS0030 fires. This **amends decision 6** ("no `BannedSymbols.txt` change"): that decision was
  about banning System.Text.Json's reflection overloads, which the analyzers already catch; a
  dependency's hidden reflection is exactly what they cannot catch, so a ban is the only compile-time
  guard. Upstream fix belongs in NetCid (moisesja/net-cid); not filed — sibling repo, owner's call.
- **`IlcTreatWarningsAsErrors=false` in the tool only.** The ILCompiler inherits the repo-wide
  warnings-as-errors and failed the publish on Newtonsoft.Json's unreachable `dynamic` support (the 10
  warnings the issue predicted, none from DataProofs). The tool's own Roslyn analyzers stay errors;
  `ac-12`'s log scan is the gate for DataProofs-attributed ILC warnings.
- **Exceptions escaping a path are failures.** Library APIs throw by contract on bad input (JweParser on
  failed decryption); the first negative control crashed the tool with exit 134 instead of `FAILED:`.
  `Program.Run` now reports them as named failures (exit 1).
